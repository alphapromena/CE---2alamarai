## Section C — ICU plural usage

`messages/{en,ar}.json` contains ~32 plural-bearing keys. **31 of 32 use full ICU `{count, plural, ...}` form in both languages.**

### I18N-01 — the one mismatch

**Key:** `Admin.dashboard.trend.summary`

```json
// en.json
"summary": "{total, plural, =0 {No check-ins} one {# check-in} other {# check-ins}} · avg {avg}/day"

// ar.json
"summary": "{total} تسجيل · بمعدّل {avg}/يوم"
```

### Why it matters

Arabic CLDR plural rules use **six** categories (`zero`, `one`, `two`, `few`, `many`, `other`). With `{total} تسجيل`:
- `total = 0` → "0 تسجيل" (should be "لا توجد تسجيلات" or use `zero` form)
- `total = 1` → "1 تسجيل" (should be "تسجيل واحد")
- `total = 2` → "2 تسجيل" (should be "تسجيلان" — dual form)
- `total = 11` → "11 تسجيل" (should be "11 تسجيلة" — `many` form for 11–99)
- `total = 47` → "47 تسجيل" (`many` form)

It still reads as a translation, just stilted Arabic. Native speakers will notice.

### Self-correction

The Phase 4 prompt explicitly allowed either form ("If the ICU plural for the English summary feels heavy, fallback to a simpler '{total} check-ins · avg {avg}/day' string is fine"). I chose ICU for EN and flat for AR, which is the inconsistent pair — should have been EN-flat + AR-flat OR EN-ICU + AR-ICU. Two ways to fix:

1. **Keep ICU on both sides** (preferred, Arabic plurals matter):
   ```json
   "summary": "{total, plural, =0 {لا توجد تسجيلات} one {تسجيل واحد} two {تسجيلان} few {# تسجيلات} many {# تسجيلة} other {# تسجيل}} · بمعدّل {avg}/يوم"
   ```

2. **Drop ICU on both sides** (faster):
   ```json
   // en.json
   "summary": "{total} check-ins · avg {avg}/day"
   ```
   The EN version becomes ungrammatical at `total = 1` ("1 check-ins") but acceptable for a dashboard summary.

I'd take option 1.

## Section F — Directional icons

Searched for `ChevronLeft`, `ChevronRight`, `ArrowLeft`, `ArrowRight` in JSX: **zero usages**. The codebase uses non-directional icon analogues (`ArrowUpRight`, `ArrowDownRight` for trend deltas — both are diagonal, mirror-symmetric in meaning).

The text-arrow `→` / `←` in `Admin.dashboard.fieldActivity.viewFull` is in the **translation string itself** (EN: "View full live ops →"; AR: "عرض اللوحة المباشرة ←"). This is the right way to handle direction-aware glyphs in i18n — push the responsibility into the translator, not the layout. ✅

(I considered using a `<ChevronRight rtl:-scale-x-100>` for the "view full" link in Phase 3 and removed it because the arrow was already in the translation string. The right call.)

| Check | Result |
|---|---|

| `focus:outline-none` without restored ring | 0 violations. Every `outline-none` is paired with `focus:ring-2` or `focus-visible:ring-*`. |
| `aria-label` on non-interactive elements | Used semantically only — `<span aria-label={status}>` on `StatusPill` (presentational container, label is the announce-able status), `<div role="group" aria-label={t('group_label')}>` on `LocaleSwitcher`. No misuses. |
| Color-only conveyed information | Status pills use color + icon + text. KPI tints are decorative — the metric is conveyed by label and number. Trend deltas use color + arrow icon + sign character (`+` / `−`). |

```css

  outline: none;
  box-shadow: var(--ring);
  border-radius: var(--radius-sm);

```
…with a separate ring for `.bg-inverse` surfaces (the dark sidebar). Belt-and-suspenders.
